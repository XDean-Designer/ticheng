先读这几条（贯穿全文）

  1. 本期为新版提成设置（原型「提成设置·实验」commission2），采用 多方案 模型：每个提成方案可整体分配给若干员工，方案内按「项目 / 产品 / 办卡 / 充卡 / 快速消费」5 项默认 + N 条覆盖规则项配置提成。每人只能分配一个提成方案；开单计提时只读该员工所属唯一方案。不同行 / 互不覆盖的计算项可相加（见 §8）。快速消费在 UI 为第 5 张默认卡，数据上是系统项目覆盖项（system: true，refId=quick），不可删除。
  2. 提成计算不再依赖旧「业绩设置」：旧「业绩设置」功能（简单模式 / 进阶基础设置）本期被完全移除，工作台不再提供入口；其“按业绩计算提成”的旧口径一律废除。存量配置按 模块 13 折叠迁入新提成方案，保证迁移前后提成金额一致。
  3. 系统内「业绩」与「业绩提成」解耦：业绩 = 流水订单按支付方式归类的金额合计，由 现金 / 卡付 / 团购 / 签单 4 部分组成（签单 = 线上「经理签单」+「记为欠款」）；业绩只作为经营统计维度，不参与提成计算，也不可人工编辑（见 §8 规则 16）。
  4. 流水订单：订单行内「业绩」只读展示，不再可编辑；「提成」仍可编辑，但需权限（店主 / 合伙人），且每次改动记录修改日志（操作人 / 时间 / 前后值），流水详情可查看（见 §6.8、§8 规则 18–19）。
  5. 提成生效时点：开单（结算）时按员工所属方案自动计算提成并写入订单行 staffCommissions；此后可在流水详情人工修正（有权限者）。薪资核算取订单行提成汇总（薪资联动本期 PRD 只给口径，不展开完整薪资规格，见模块 2）。
  6. 每条提成规则的提成范围为支付方式多选：现金 / 卡付 / 团购 / 签单 四类（签单 = 经理签单 + 记为欠款）。范围外的支付方式对应订单行不计提成。
  7. 原型工具栏「无数据 / 有数据」造数仅演示，不进正式产品。接口路径标 【待联调确认】，正式接口文档暂无交付时间；不臆造现网 URL。
  8. 本期仅单店；旧「提成设置」中的阶梯提成方案 完整保留并继续生效（走旧阶梯引擎，不迁入新模型，见 §13.1）；旧单项提成按模块 13 迁为新方案。新老并存时：阶梯员工读旧引擎，已迁单项员工读新引擎。

模块 1　背景 / 目标 / 范围 / 能力映射

读者：前端 ✓ · 后端 ✓ · 测试 ✓

1.1 背景

旧提成为「阶梯比例」单方案模型，且提成计算依赖旧「业绩设置」产出的计算基数；「业绩设置」同时承担业绩口径配置，职责混叠、配置链路长，商户难以表达“不同分类、不同支付方式、不同工位”的差异化提成。

本期重构为多方案提成设置：

  • 方案化：一套提成规则即一个「提成方案」，可命名、复制、整方案分配员工；每人只能分配一个方案，适应多岗位（顾问 / 技师 / 销售）并存的门店。
  • 规则块化：方案内 5 项默认（项目 / 产品 / 办卡 / 充卡 / 快速消费）+ 用户覆盖规则项（指定项目、产品、会员卡、整类分组）；快速消费在数据上为系统项目覆盖项。
  • 口径独立：提成基数 = 订单行原价 / 实收（按规则配置），不再经过旧「业绩设置」；旧「业绩设置」整体移除。
  • 业绩解耦：业绩回归“支付方式统计”属性（现金 / 卡付 / 团购 / 签单四部分），只读、不参与提成、不可手工改。
  • 流水闭环：开单自动写提成 → 流水详情可查看 / 人工修正（店主 / 合伙人）→ 改动留痕可审计。

1.2 目标

目标 说明
多方案并存 多套方案并存；每人只能分配一个方案（不可跨方案）
规则可分层 5 项默认（含快速消费系统覆盖）+ 用户覆盖规则项
口径独立 计算基数（原价 / 实收）与支付范围（现金 / 卡付 / 团购 / 签单）由规则自定，不依赖业绩设置
分配灵活 方案整体分配员工；工位（默认大 / 中 / 小工，可改名 / 删除，不可新增）参与按工位分配
业绩解耦 业绩 = 现金 + 卡付 + 团购 + 签单；只读展示，不参与提成、不可编辑
流水可审计 开单自动算提成写行；详情可查看，人工修正（店主 / 合伙人）留修改日志

1.3 本期做（In）

  • 提成方案列表（新建 / 重命名 / 复制 / 删除；未分配员工提示）
  • 方案编辑页：5 项默认规则卡（含快速消费）+ 覆盖规则项卡 + 「添加规则项」
  • 规则设置 Sheet：提成范围（4 类支付方式）、计算基数（原价 / 实收）、分配模式（不分工位 / 按工位）、提成取值（按比例 % / 固定金额 ¥）、点客 / 散客参数（按工位时逐工位）
  • 工位设置 Sheet：改名（恢复默认 / 确定）、删除（至少保留 1 个）；不可新增工位
  • 添加规则项页：类型 Tab（项目 / 产品 / 会员卡）+ 分组筛选 + 多选（含整类分组）+ 已配置项禁用
  • 分配员工 Sheet（员工池多选、全选、清空；已被其他方案占用的员工灰显不可选）
  • 规则卡「固定」标签：提成参数=固定金额时，规则卡计算基数标签改显「固定」（#A7E6A7），忽略计算基数设置；提成参数统一在规则设置 Sheet 的「提成取值」分段中设置
  • 左侧导航「关联页面」区域（位于「页面链路」与「文档」之间）+ 三个并列入口：「选择员工（3工位）」「选择员工（2工位）」「选择员工（1工位）」；共用灰底页 + Sheet（纯演示）
  • 试算口径：示例订单行按员工方案集合计算提成（原型试算引擎）
  • 流水订单：业绩只读展示；提成可编辑（店主 / 合伙人）；修改日志记录与查看
  • 工作台移除「业绩设置」入口；旧单项提成配置下线；阶梯提成入口与方案保留并继续生效
  • 历史数据迁移（模块 13）：业绩设置 + 单项提成 → 新提成方案；多层等价校验门禁通过后方可切换读路径
  • 权限：achCommSet 仅店主 / 合伙人；流水提成编辑仅店主 / 合伙人

1.4 本期不做（Out）

  • 员工薪资核算页的完整规格（提成汇总口径见「先读这几条」第 5 条，薪资页其余逻辑另模块）
  • 业绩排行 / 业绩报表（仅业绩四部分统计口径在本文定义）
  • 多门店提成配置与同步（本期仅单店）
  • 正式提成结算单 / 工资条打印
  • 原型的「无数据 / 有数据」造数开关
  • 阶梯提成迁入新模型（本期仅保留旧引擎生效；新阶梯能力另期设计后再迁）
  • 新提成规则块内「扣成本」一等公民字段（迁移用快照折叠；长期增强另期）

模块 8　业务规则

读者：前端 ✓ · 后端 必看 · 测试 必看

  1. 一人一方案：一个员工同时只能属于一个方案；开单计提时只读其所属唯一方案。脏数据冲突时保留最先出现的方案并剔除其余。
  2. 按行过滤：每笔订单行先按支付方式对照命中块的「提成范围」；不在范围则本行不计提成。
  3. （废除）重叠取最高：因一人一方案，不再存在「同人多方案取最高」。
  4. 不同行可相加：不同业务行、或互不覆盖的计算项，可分别计入后相加。
  5. 覆盖优先于默认：解析顺序——先按目标匹配覆盖规则项（含系统快速消费 refId=quick；单项目 / 产品 / 会员卡按 kind+refId；整类分组按 groupKind+refId），未命中回落到分类默认块（项目→labor、产品→sales、办卡→issue、充卡→card）。快速消费行（kind=quick / 名称「快速消费」）只命中系统覆盖，不吃项目默认。
  6. 计算基数：baseMode=list 用该行原价加总；baseMode=paid 用该行实收加总（§6.9 帮助口径）。签单（经理签单 / 记为欠款）订单行若规则范围含「签单」，照常参与计提，基数口径同上。
  7. 分配取值：pickMode=avg（UI「不分工位」）用规则级点客 / 散客；pickMode=station 用订单行工位对应工位的点客 / 散客；工位缺失时回退规则级点客 / 散客。
  8. 金额计算：pct → round(base × rate / 100)；amount → 固定金额（点客用 designatedAmt / 散客用 nonDesignatedAmt）。
  9. 范围合法性：任一默认块 / 覆盖块的 payScope 至少 1 类；保存时全校验。
  10. 已配置防重：目标已被覆盖（含被整类分组覆盖、含系统快速消费）→ 添加规则项列表灰底白勾禁用，不可重复添加。
  11. 整类与单项互斥：添加规则项勾选整类组会清掉组内单项勾选；勾选单项会清掉涵盖它的整类勾选。
  12. 工位：可改名 / 删除（至少 1 个）；不可新增；删除工位同时清除各规则块该工位参数。
  13. 未分配提示：员工池中存在不属于任何方案的员工 → 列表提示「还有 N 人未分配提成」；全部有方案则隐藏。
  14. 复制语义：复制方案清空分配（assigneeIds=[]），规则与工位原样（含系统快速消费）。
  15. 支付范围四类：现金、卡付、团购、签单（= 经理签单 + 记为欠款）；原型 COMM2_PAY_SCOPE 以本期扩展为准（现金 / 卡付 / 团购 / 签单）。
  16. 业绩与提成解耦：业绩 = 现金 + 卡付 + 团购 + 签单四部分合计，只读展示、不参与提成计算、不可人工编辑。
  17. 旧「业绩设置」移除：工作台「业绩设置」入口删除；旧口径（按业绩算提成）一律不再使用。
  18. 流水提成编辑权限：仅店主 / 合伙人；其余角色点击提成编辑被 toast 拦截。
  19. 流水修改日志：提成每次人工改动写 editLogs（复用现有修改记录，结构 {id, time, operator, summary}），summary 记录前后值（如「修改提成：8.00→10.00」），详情「修改记录」可查。
  20. 本期仅单店；方案数据不跨店同步。
  21. 快速消费系统卡：UI 为第 5 张默认卡；数据为 overrides 中 id=ov_sys_quick、system:true、targets=[{kind:'project', refId:'quick'}]；初始参数与「项目」默认相同；不可删除。

  32. Given 按工位分配且三工位均有参数，When 第一行宽度仅容两个工位段，Then 放不下的工位段（如「小工 …」）整段换至参数第二行且右对齐；chevron 不与参数重叠。
  33. Given 任意规则卡，When 查看布局，Then 第一行 = 标题 + 提成参数（同行）；第二行 = 计算基数标签 + 提成范围胶囊；chevron 相对整卡垂直居中。
  34. Given 不分工位规则，When 参数区极窄，Then 「点客X·散客Y」整段换行，不在「点客」「散客」之间拆开。
  35. Given 规则卡列表，When 查看卡片，Then 无「比例 / 固定」切换控件；点击卡片打开规则设置 Sheet。

模块 13　历史数据迁移（业绩设置 + 单项提成 → 新提成设置）

读者：前端 了解 · 后端 必看 · 测试 必看
文档版本自 v1.3 起纳入；目标：迁移不改变提成计算结果。

13.1 目标与边界

目标：迁移后，对同一笔订单行，每位员工提成金额与迁移前逐分一致（同一 round 规则）。

范围处理
业绩设置（高级设置 + 按项业绩% + 按项手填成本）+ 单项提成转换为新 Scheme（defaults + overrides + assigneeIds）
阶梯提成不转换；配置完整保留并继续生效（旧阶梯引擎）
新「业绩」四部分统计与提成解耦，不参与提成

13.1.1 阶梯提成「保留并继续生效」硬性约束

层级要求
数据阶梯方案表/字段 只读保留；迁移 Job 禁止写入、覆盖、归档删除阶梯配置
路由结算：员工若绑定阶梯方案 → 必须走旧阶梯引擎；仅已迁单项/新方案员工走新引擎
一人一方案不得同时生效「阶梯 + 新单项」；历史双绑 → needs_review 并 阻断 该员工切换，默认 优先阶梯 直至人工处理
UI新列表可展示阶梯方案（只读标签「阶梯·沿用旧版」）；编辑进旧阶梯页；不可被「保存新方案」误覆盖
入口下线业绩设置、旧单项配置；阶梯配置入口保留至二期
回归每门店层 D：阶梯配置 hash + 历史回放金额不变 + 路由探针（§13.6.4）

13.1.2 已确认业务口径

项结论
旧单项提成公式提成 = 业绩额 × 提成比例；固定金额则直接取 ¥
业绩额max(0, (售价或实收 − 成本) × 业绩%)；成本在业绩按项里手填
高级设置「按售价 / 按实收 / 不计算」直接决定提成基数口径；不计算 → 该口径提成基数为 0
会员卡开卡 → 办卡；充值 + 续次 + 续费(延期) → 充卡
签单实收 = 0，按此逻辑计算（实收模式下提成自然为 0）
赠金耗卡 / 赠送服务 / 商城 / 抵用券M1：并入最接近分类并折算；无法精确等价则 needs_review
分配业绩「平均/按工位」影响分业绩；提成是否按工位以单项提成配置为准
方案归属多套单项提成 → 多个新方案，保留员工归属

13.2 新旧公式对齐

13.2.1 旧引擎（单项）


price  = 售价(原价) 或 实收    // 由该分类高级设置决定

cost   = 按项手填成本（无则 0）

achPct = 按项业绩%（默认 100%）

comm   = 点客或散客提成比例；或固定金额



若「不计算」: 提成 = 0

若固定金额:   提成 = 点客/散客（及工位）对应固定 ¥

若比例:       业绩额 = max(0, (price − cost) × achPct)

              提成   = moneyRound(业绩额 × comm)

13.2.2 新引擎


base = line.list | line.paid     // RuleBlock.baseMode

若 payScope 不含该支付方式: 0

若 valueMode=amount: 固定 ¥

若 valueMode=pct:    moneyRound(base × rate / 100)

新模型无「成本」「业绩%」字段：迁移时将旧参数折叠进 baseMode + rate/amount（必要时写入按项 overrides）。

13.2.3 比例折叠恒等式

对快照价 P（list→资料原价；paid→资料价或近 90 天实收中位数，见 §13.5）：


旧: moneyRound( max(0,(P−cost)×achPct) × comm )

新: moneyRound( P × newRate / 100 )



当 P>0:

  newRate = comm × achPct × max(0, P − cost) / P

  （旧 comm 若已是百分数，按同一百分数语义换算，禁止混用 0–1 与 0–100）
情形处理
cost=0 且 achPct=100%newRate = comm，可进分类默认，与价无关
cost>0 或 achPct≠100%必须按项覆盖；依赖快照 P；列入「改价敏感」报告
固定金额直写 valueMode=amount，不折叠

13.5 迁移算法


读取门店旧配置

├─ 阶梯 → 原样保留并继续生效（层 D 回归）

└─ 单项 → 生成 Scheme 壳

         → 工位名映射

         → 高级设置写 defaults.baseMode

         → 单项提成写默认 CatRule

         → 按项折叠 achPct/cost → overrides

         → 会员卡三类合并检测

         → 写入 assigneeIds

         → 多层等价校验（§13.6）

              ├─ 全通过 → 仅切换「已迁单项员工」读新引擎

              └─ 失败 / needs_review → 阻断切换并出报告

按项折叠伪代码


for each 项目/产品/卡规则:

  if 固定金额: 直写 amount; continue

  if 分类不计算: rate=0; continue

  P = snapshotPrice(item, baseMode)

  if P<=0: needs_review; continue

  newRate = comm * achPct * max(0, P - cost) / P

  if cost==0 and achPct==1 and 与分类默认相同: 可省略覆盖

  else: 写入 override

幂等：Scheme._v3 + migrationBatchId。阶梯数据 永不 被 batch 覆盖。

13.6 等价校验（迁移不改数的硬门槛）

原则：切换前证明「配置折叠正确」+「引擎结果一致」+「阶梯未受影响」。任一层失败则门店不切换。

13.6.0 Round 与金额单位（Day0 锁定）

从旧源码锁定并单测固化：金额单位（分/元）、舍入函数与乘除顺序。

新引擎与迁移折叠 必须调用同一 `moneyRound`。

13.6.1 层 A · 配置折叠自洽

检查通过条件
固定金额点客/散客（及工位）金额逐项相等
比例且 cost=0、achPct=100%newRate == 旧 comm
比例需折叠快照 P 上旧(P)=新(P)；并对 P±1 分 邻域探测
不计算新 rate/amount 全 0

13.6.2 层 B · 合成订单双跑

每门店 ≥ 300 条样本（不足则补齐笛卡尔积）：

分类 × 点客/散客 × 三工位 × 四支付；每个实际 override 至少命中 1 行；含 cost>0、achPct≠100%、不计算、固定金额、快消、商城、实收=0 签单。

旧单项引擎(line) vs 新引擎(scheme, line) → 分位全等。

13.6.3 层 C · 历史流水回放

近 90 天（或至少 50 单）已结账流水：

仅单项员工重算；与旧引擎（或可复算存档）一致。

manual_edited 人工改提成 不纳入门禁，单独报告。

13.6.4 层 D · 阶梯未受损回归（强制）

  1. 阶梯配置迁移前后 hash 一致
  2. 阶梯员工历史订单回放金额不变
  3. 路由探针：仅绑阶梯员工的结算 未进入 新 Scheme 路径

任一项失败 → 全店阻断。

13.6.5 层 E · 属性加固（推荐）

  • cost=0 且 achPct=100%：随机 P 抽样 20 次新旧全等
  • cost>0：仅保证快照 P；报告「改价敏感」

13.6.6 门禁与发布


通过 = A ∧ B ∧ C(非人工) ∧ D ∧ needs_review 为空
  • 不通过 → 不切换；出 diff / 改价敏感 / 卡冲突 / 双绑报告
  • 通过 → 仅切换已迁单项员工读路径；阶梯不变
  • 回滚：useLegacyItemCommission（仅单项，与阶梯独立）

13.6.7 上线后观察

灰度双写 ≥7 天（仅单项员工）；阶梯监控「是否误入新引擎」告警。再关旧单项配置入口。

13.7 已知非恒等风险（须产品接受）

  1. 扣成本 + 日后改价：快照折叠；改价后可能漂移 → 报告改价敏感；二期可加 deductCost
  2. 实收近似 P：未过层 A/B 不得上线
  3. 充值≠续次≠续费 难区分 → 人工确认
  4. 赠金/赠送/抵用券 标签不全 → 复核，禁止静默
  5. 阶梯 不迁入新模型；用层 D 保证继续生效且金额不变
